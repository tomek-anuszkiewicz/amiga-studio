# Stage 08: Proofreading

Stage 08 reads all retained final page objects from Stage 07. For each selected page it first sends ordered text objects and short boundary excerpts from neighboring retained pages to the shared Codex client. If that response has unresolved items, Stage 08 sends the current page text, those items, and its Stage 02 page image in a second request. The image response makes a final decision for each flagged segment: correct its text or leave it unchanged with a reason. It writes every selected page, including unchanged pages, to `08_proofreading/page_*_segments.json`. Only validated `md_text` replacements are applied; other JSON fields and object order are preserved.

Stage 08 uses the `08_proofreading` model settings in `config.yaml`, the shared request cache and stage metrics. The first request contains no image or complete Stage 02 positioned text. The second request contains the full page image only when the first response needs visual evidence. The two requests have separate cache keys. The only Stage 08 page output is the complete proofread `page_*_segments.json`; it does not produce issue counts or review reports. Book import requires Stage 08 success and reads all retained Stage 08 pages. A selected-page restart clears selected Stage 08 page files.

The console shows each page request, response call and cache-hit counts, an image request when needed, and `done` after writing the page. `--trace-codex` adds content-free request send, wait, completion and failure events. With one configured worker, conversion runs on the invoking thread so `Ctrl+C` can interrupt the wait between requests. Abrupt process termination can leave the last stage status as `running`; check that no pipeline or proofreading process remains before restarting.
