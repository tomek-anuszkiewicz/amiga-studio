# Model and Reasoning Advice

- Preserve the user's selected model and reasoning effort unless they request a change. Never guess unavailable session metadata or supported effort levels.
- Offer concise advice only when task complexity or observed difficulty gives a concrete reason: cycle-exact architecture and subtle timing diagnosis may need more reasoning; proven mechanical procedures may need less.
- Do not classify all documentation or opcode work as easy, promise correctness from a higher effort, or repeat recommendations as routine status messages.
