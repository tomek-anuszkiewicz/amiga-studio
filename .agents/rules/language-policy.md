# Language Policy

- Answer in the language of the user's current request unless asked to switch.
- Persist repository code, identifiers, comments, documentation, plans, diagnostics, commits, and PR descriptions in English.
- Translate user concepts into idiomatic English before writing them into repository artifacts; do not quote untranslated prompt phrases or metaphors in code or comments.
- Spoken-input presentation follows [audio-transcription.md](audio-transcription.md).
- Every `python tests/verify.py --commit` scans all repository-owned text files, including unchanged files and nonignored new files. The milestone profile uses the same full scan. Staging is not required. Explicit scanner commands are in [agent maintenance](../references/agent-tooling.md#recording-and-validating-changes). Use no hooks.
- Maintain the scanner's scope in [check_english.json](../../tests/checks/check_english.json), the authoritative directory, file and text-format exclusions. Git-ignored untracked files are also omitted. Directory names apply at any depth; directory paths are repository-relative subtrees. Explicit file arguments bypass these exclusions.
- When adding or discovering generated output, caches, benchmark result trees, vendor code or imported reference collections, review this scope before verification and exclude irrelevant data at the directory boundary. Keep authored code, tests, specifications, rules and documentation covered; do not exclude authored content to hide language findings. Add new authored text formats to the extension list. Lockfiles and binary formats are not selected. The scanner itself is included; the scope catalog is excluded because it stores deliberate invalid example literals.

- The English gate checks each word against `pyspellchecker` and the reviewed vocabulary in [english_words/](../../tests/checks/english_words/). Unknown words are findings, not language classifications. The scanner splits identifiers, accepts possessive forms, and omits URLs and numeric literals; uppercase words are still checked. Use half the available logical CPUs, rounded down, with a minimum of one and a maximum of six scan processes; for smaller file sets, cap the process count at the number of files.
- Report each unknown word with its file, line and context. Suggest similar dictionary or approved vocabulary words when available, describing a suspected typo as a suggestion rather than a confirmed error. Otherwise explain that the word is unknown and may need correction or an approved exception. Do not automatically correct suspected typos, add vocabulary entries, expand exceptions or suppress findings. Leave findings unresolved until the user explicitly decides whether to correct the text or allow the word.
- After the user's decision, maintain one explicit approved term per line in the appropriate programming, hardware, software or names list; record only verified terms and names, never accept an unreviewed scan output. Inflected forms need their own entries. Deliberate invalid or non-English literal examples belong in the scope configuration's exact-file `file_words` map, never in a global word list. Apply approved spelling corrections at the source instead of adding misspellings to the vocabulary.
