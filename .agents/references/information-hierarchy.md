# Document and instruction ownership

- Root [AGENTS.md](../../AGENTS.md) defines the shared rules for scope,
  authorization, preservation, evidence, language and portability. It identifies
  relevant technical requirements and explains how to choose skills, delegate
  work and select models and reasoning effort based on the user's request and
  authorized scope.
- Shared references define applicable technical requirements. Specifications
  govern approved behavior and architecture. Review references define the detailed
  standards for results, including naming, cohesion, test adequacy and narrative.
  The standards apply even if the author has not read those references.
- The user selects outcomes and scope through ordinary language or named skills.
  The main session applies root routing instructions to select the matching skill
  and executor. The skill states how the selected operation runs and where it
  ends. Further stages require authorization beyond a reference or finding.
  Tools and checkers define what they run, the formats they use and the
  conditions for passing.
- Keep one authoritative home per requirement, criterion or procedure. Update
  incoming links and directly affected criteria when changing that requirement.
  Preserve exact exceptions and earliest action-time obligations when moving text;
  generic advice already supplied by routine competence need not be relocated.
- Reader-facing `docs/` explains the project and provides useful entry points.
  Operational detail belongs with tools/skills; history belongs in diary/Git.
  [Documentation Value](documentation-criteria.md#documentation-value) governs retained
  requirements, evidence and rationale without a deletion quota.
- Do not create duplicate operation registries or forwarding rule files. Read only
  material relevant to the requested work. Reviewers use their assigned criteria and
  relevant requirements without inheriting the author's conversation or other lanes.
- When changing instructions or governance, assess affected review criteria as
  part of the same change. Unaffected areas of review need no cosmetic edits.
  Report what the checks actually enforce and their runtime limits. Their names
  alone give no evidence of semantic coverage.
