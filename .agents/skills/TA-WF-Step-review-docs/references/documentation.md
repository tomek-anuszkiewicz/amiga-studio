# Specifications, documentation and governance

Apply the shared [documentation criteria](../../../references/documentation-criteria.md)
and the relevant requirements for instruction ownership and specifications.
They explain how to select the scope for compliance, what milestones require
and how to assess a document's value. Use them within this skill. A separate
public skill starts only when selected.
Apply the shared [prose and narrative criteria](../../../references/narrative-criteria.md)
according to the document's purpose; preserve unique evidence and reasoning when
assessing reorganized articles or other documentation. Review approved
requirements and retained source-backed knowledge in both directions under the
shared scope rules; stage-wide assessments include unchanged affected material.

Trace changed requirements into affected code and tests even when the
implementation has no diff. Assess the supplied results of required audits and
what they covered without rerunning them. Distinguish corrections that update
a description from those that change a requirement. Identify other lanes affected by changes to criteria
or evidence. For changed instructions, follow a real invocation to check which
document owns the procedure, how it starts and stops, and what still calls it.

Use this skill's full Design audit to check what the metadata and links mean.
Assess any diary or roadmap obligations the change triggers. Preserve hardware
knowledge, independent requirements and unique reasoning. Report additions or
repairs needed. Leave document edits, indexing and unrelated audits outside
the assessment.

Check that explanations are concise, stay within what the evidence supports and
use the user's language.
Assess the small shared result format and actual selected operation, without
requiring a transition matrix, fixed review lanes or a lifecycle record.
For instruction changes, verify that active callers no longer invoke removed
commands and that remaining operational requirements have one authoritative owner.
