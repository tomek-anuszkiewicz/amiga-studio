# Tests and verification evidence

Apply [testing criteria](../../../references/testing-criteria.md), relevant
[testing policy](../../../rules/unit-testing-policy.md), batch authority when
triggered, and the [verifier contract](../../../../tools/verification/README.md).

- Map changed behavior and interactions to independently expected assertions.
  Executed lines, changed test files and aggregate percentages alone do not
  establish meaningful protection; distinguish fixtures from production integration.
- Review current changed-code coverage when required for production changes,
  including uncovered spans, measured suites, conditional targets and object mapping.
  Separate pre-existing gaps; unresolved required in-scope gaps block readiness.
- Check actual commands/outcomes, candidate/condition identities, intact artifacts
  and retained-evidence validity. Failed, missing or invalidated groups are not passes.
- Treat the versioned timing report as generated output. Its updates must preserve
  selection/continuation while real source changes remain detected; it certifies no gate.
- Distinguish renewed reviews from carried scoped approvals and inspect the comparison
  supporting retained content, requirements, criteria and evidence. Canonical reuse
  remains the verifier's responsibility.
- Check concrete approval for architectural checks/policy, weakened assertions/gates,
  goldens and references. An approved contract change may authorize the corresponding
  ordinary test update; a review finding alone does not.
- Batch preparation requires passing canonical evidence for the combined final
  candidate; milestone gates keep their actual trigger. A standalone review does
  not launch batch preparation.
- Assess partition coherence and claims about intermediate commits and unrun
  hardware, platform or performance work. Integration evidence covers assembled
  history and complete candidate, not merely separately passing source branches.
  Inspect source-tip preservation, failed-publication safety and partial cleanup.

For Graphify changes, require relevant evidence for corpus isolation, ignore-setting
preservation, semantic preservation/removal, query provenance and read-only behavior,
explicit bootstrap updates to both graphs and project-only worktree refresh.
Exercise evidence must include actual native traversal and all graph artifacts plus
any query log; unchanged graph.json alone does not prove a read-only query.

For changed PowerShell tools, assess the focused evidence in the
[PowerShell result criteria](../../TA-write-powershell/references/acceptance.md).

For guidance trials, distinguish actual selection-to-execution evidence from
rendered proposals and inspected boundaries. Verify correct executor/skill/scope,
no dispatch before selection, preserved failures and candidate freshness. Record
delegated coordinator choices as such. Do not invent interrupted/exhausted results
or weaken protected tests to demonstrate an approval branch; report unexercised
branches and respect the prohibition on automated workflow-test infrastructure.

Check official matrix cell/condition validation and the distinction between a
marked edge and satisfied prerequisites. Missing cells must reject unsolicited
official suggestions while ordinary user-directed invocation remains available.
Distinguish data-validation probes from real agent execution and preserve original
guidance/evidence when the format or matrix changes.
