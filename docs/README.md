# Understanding the Project

The documents in this directory introduce the Amiga 500 emulator to users,
developers and people interested in its development. They explain the main ideas,
show how the parts fit together, and point to useful starting places. Choose the
question you want to answer:

| Question | Start here |
| --- | --- |
| How does the emulator model an Amiga? | [Architecture](architecture.md) |
| How do I inspect or step through execution? | [Developer Studio and debugger](debugger.md) |
| How do I run the project and find the relevant code? | [Developer orientation](developers.md) |
| What do the tests establish? | [Verification overview](testing.md) |
| How do I collaborate with a coding agent here? | [Working with an AI agent](ai_agents.md) |
| How was the project developed? | [Development story](how_this_emulator_was_written.md) |

For detailed subsystem contracts, use the
[design index](../Obsidian/Amiga/Design/General%20Architecture.md). Operational
procedures live with their tools, tests or owning agent skills and rules.
When asking an agent about a specific behavior, use these overviews to identify
the area and ask it to inspect the relevant implementation, specifications and
test evidence.
